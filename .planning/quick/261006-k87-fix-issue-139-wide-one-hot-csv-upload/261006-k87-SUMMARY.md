
## Branch Order Actually Implemented

Matches the plan's D-02 order exactly, no deviation:

1. `read.csv(path, stringsAsFactors = FALSE)`.
2. If `cause1` present and `cause` absent → rename; log (job_id non-NULL only).
3. If `ID` and `cause` both present → return the LONG frame immediately (extra columns ignored).
4. Otherwise, WIDE candidate: `matched` = columns whose `normalize_cause()` is in
   `normalize_cause(get_broad_causes(age_group))`; `leftover` = the rest.
   - `length(matched) == 0` → `unrecognized_layout_stop()`.
   - `length(leftover) >= 2`:
     - if any leftover normalizes to the **other** age group's broad causes →
       `unrecognized_layout_stop()` (the `pneumonia`/`other` overlap case from the plan).
     - else → ambiguous-ID `stop()`, naming every leftover column verbatim.
   - `length(leftover) == 1` → that column (`as.character()`) is the ID.
   - `length(leftover) == 0` → synthesize `row_1 … row_n`.
5. Coerce matched columns via `suppressWarnings(as.numeric(as.character(as.matrix(df[matched]))))`.
   Any `NA` → numeric-cells `stop()`.
6. Any value outside `{0,1}`, or any row summing `> 1` → single-cause `stop()` (first 5 offending
   IDs + `+N more`).
7. Row sum `1` → canonical broad name of the hit column (via `get_broad_causes()`, mapped through
   `normalize_cause()`, never the user's spelling). Row sum `0` → `"Unspecified"`.
8. `job_id` non-NULL and the WIDE branch was taken → one `add_log()` line (record count + ID
   column name or "synthesized").

`unrecognized_layout_stop()` is a local closure: calls `validate_causes(names(df), age_group)`
inside `tryCatch` (passing the **full** column set, per the plan, so the hint counts every
offending column), captures `conditionMessage(e)` when it throws, and appends a paragraph naming
both accepted layouts.

## Error Messages As Shipped

Four distinct `stop()` call sites (the plan's token contract table has four rows; "three new
messages" in the context doc groups the single-cause and multi-cause cases together since they
share one message):

**1. Numeric-cells error** (NA after coercion — blank, `TRUE`/`FALSE`, text):
```
Column(s) %s must contain only numeric 0/1 values. Non-numeric cell(s) found in record(s): %s%s.
```

**2. Single-cause error** (value outside {0,1}, or row sum > 1 — probabilities or multi-cause):
```
The wide layout must contain single-cause 0/1 indicators (exactly one 1 per row) -- found
probabilities or multiple causes in record(s): %s%s. Export single-cause assignments rather than
probabilities.
```

**3. Ambiguous-ID error** (>=2 leftover columns, none matching the other age group):
```
Could not tell which column holds the record ID: %d candidate columns found (%s). Rename the
intended ID column, or remove the extra one(s), and re-upload.
```

**4. Unrecognized-layout error** (0 matched, or >=2 leftover with an other-age-group hit):
```
<captured validate_causes() message verbatim, including its wrong-age-group hint when applicable>

This dashboard accepts two CSV layouts:
  1. Long: an 'ID' column and a 'cause' (or 'cause1') column.
  2. Wide: one 0/1 column per broad cause for age_group='%s' (%s), plus an optional single ID
     column (any name, or none).
```

All four satisfy the plan's `<error_token_contract>` tokens (verified by section 31's 26
assertions): `single-cause`, offending IDs + `+N more`, `numeric`, `which column holds the record
ID`, leftover column names verbatim, the captured `validate_causes` wrong-age-group hint, and the
`ID`/`0/1` literals in the accepted-layouts paragraph.
