accepted (preview endpoint, single-file job, multi-file ensemble job), with no change to
any downstream helper.

### D-02 Layout detection by column set — no ID-column name list
Order of rules inside `read_cause_upload`:
1. If `cause1` present and `cause` absent → rename to `cause` (existing behavior).
2. If columns contain `ID` and `cause` → LONG layout. Extra columns are ignored (existing
   behavior; the dashboard is deliberately more permissive than the package here).
3. Else → candidate WIDE layout: `normalize_cause(names(df))` matched against
   `normalize_cause(get_broad_causes(age_group))` (utils.R:524, :538).
   - ≥1 broad-cause column matched, and the LEFTOVER (non-matching) columns number:
     - exactly 1 → that column is the ID column, whatever its name (`X` from an unnamed
       header, `ID`, `id`, `uuid`, …); IDs = `as.character()` of it.
     - 0 → synthesize IDs `"row_1" … "row_n"`.
     - ≥2 → `stop()` naming the leftover columns (e.g. a `Total` column): the reader must
       not guess which one is the ID.
   - 0 broad-cause columns matched → first call `validate_causes(names(df), age_group)`
     (utils.R:556) so its existing wrong-age-group hint and expected-cause list are
     reused when the columns are the OTHER age group's broad causes; if that returns
     without stopping, `stop()` with a message listing the two accepted layouts
     (long: `ID` + `cause`/`cause1`; wide: one 0/1 column per broad cause for this age
     group, optional single ID column).
   Missing broad-cause columns (a subset of the 6/9) are fine: the long frame simply has no
   rows for them; `build_broad_matrix` emits zero columns and the existing zero-death
   exclusion (#101) handles them.

### D-03 Wide values must be 0/1 with row sum ≤ 1
- Coerce each broad-cause column with `suppressWarnings(as.numeric(as.character(x)))`.
  Any NA after coercion (blank cells, `TRUE`/`FALSE` strings, text) → `stop()`.
  Any value not in {0, 1} → the "looks like probabilities" error below.
- Per row, over the broad-cause columns: sum 1 → `cause` = the canonical broad name of the
  hit column (from `get_broad_causes`, not the user's spelling); sum 0 → `cause =
  "Unspecified"` so the EXISTING undetermined-cause pipeline (`drop_undetermined_causes`,
  utils.R:182; `UNDETERMINED_CAUSES`, :175) logs and excludes it in the job path and the
  preview reports it under `excluded_undetermined` (its `total_records ==
  excluded + calibrated + unrecognized` invariant holds); sum > 1 → error.
- The probabilities/multi-cause error names the offending row IDs (first 5, "+k more") and
  says: the wide layout must contain single-cause 0/1 indicators (exactly one 1 per row);
  export single-cause assignments rather than probabilities. This mirrors
  `vacalibration()`'s own `singlecause.check` (row sum must be 1 and exactly one nonzero)
  with a clear message and the all-zero leniency.
- Duplicate IDs need NO new code: `assert_all_causes_mapped` already rejects them.
