## Accomplishments

- Installed vacalibration 2.3.1 locally from GitHub at the pinned commit; only `LaplacesDemon` was added as a new dependency, and `rstan 2.32.7` / `StanHeaders 2.32.10` stayed identical to the image manifest.
- Edited `backend/Dockerfile`: the CRAN install line now installs only `openVA`, `EAVA`, `knitr`; a new `RUN` step installs `remotes` from the snapshot, then `remotes::install_github()` at the full 40-char SHA with `upgrade = 'never'` and a build-time `stopifnot()` on the installed version. `ENV CRAN_SNAPSHOT` and the Stan compile step are byte-for-byte unchanged.
- Updated `backend/package-manifest.csv`: `vacalibration,2.2` → `vacalibration,2.3.1`, plus the new `remotes,2.5.0` row inserted between `rematch,2.0.0` and `reshape2,1.4.5`. - Ran the tracer proof: `vacalibration()` on `frontend/public/sample_eava_child.csv` via `build_broad_matrix()`/`build_donotcalib()` excluded `injury`, `other`, `nn_causes` (not malaria), returned a full `1x9x9` `Mmat_tomodel`, and `lambda = 0.39` (not stalled).
- Added a new section to `tests/test_dockerfile_pinning.R` (`VACAL_SHA` constant + 6 new assertions) that fails the build if the vacalibration ref is ever not the pinned 40-hex commit SHA, if any `install.packages()` line still names vacalibration, if the GitHub install stops disabling dependency upgrades, or if the manifest disagrees with the Dockerfile. Assertion count: 28 → 34.
- Verified the mutation guard: swapping the SHA for a branch-shaped ref fails exactly the 2 new SHA-format assertions and exits 1; the Dockerfile was restored byte-identical afterward (`cmp -s` confirmed).

## Decisions Made

- Chose `remotes::install_github()` over an archive-tarball `R CMD INSTALL` for the pinning mechanism (D-01 left this to planner/executor discretion) — it keeps the same `options(warn=2)` failure-attribution property as every other install line in the Dockerfile and needs only one new CRAN-snapshot dependency (`remotes`).
- Placed the new SHA-pinning test section between the existing CRAN-snapshot section and the sodium section, per PATTERNS.md, so all "no floating references" guards stay grouped.
- The new manifest-row assertion resolves its file path the same way `dockerfile_path` does (root vs. `backend/` invocation) rather than depending on the `repo_root` variable computed later in the file — R executes top-to-bottom and the new section runs earlier, so reusing an as-yet-undefined variable was not an option; the dual-entry-point resolution already established in the file is the equivalent, working pattern.

## Post-review fixes (PR #132 code review)

- `remotes::install_github()` replaced by `install.packages(<GitHub archive tarball>, repos = NULL, type = "source")`, driven by a new `ENV VACALIBRATION_SHA` beside `CRAN_SNAPSHOT`. The remotes path made three anonymous api.github.com calls per uncached build under the 60/hour per-IP limit shared by runner egress; codeload is not rate-limited that way. `remotes,2.5.0` is gone from the manifest (135 rows again). The build-time version `stopifnot()` was dropped: the SHA is content-addressed and the deploy manifest diff already checks the installed version.
- Pinning guard now counts occurrences of `sandy-pramanik/vacalibration` rather than lines, so a second install chained on the same physical line fails CI (mutation-tested). 38 assertions.
- knitr comment corrected: it is a hard runtime dependency because both backend call sites pass `verbose = TRUE` and `vacalibration()`'s verbose branch calls `knitr::kable()` unguarded.
