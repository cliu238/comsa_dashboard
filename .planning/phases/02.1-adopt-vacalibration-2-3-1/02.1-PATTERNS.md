### `tests/test_dockerfile_pinning.R` (test, source-assertion)

**Helper pattern to reuse** (lines 20-38, already in file, do not redefine):
```r
test <- function(desc, expr) {
  .test_count <<- .test_count + 1L
  tryCatch({
    ok <- eval(expr, envir = parent.frame())
    if (!isTRUE(ok)) stop("assertion returned FALSE")
    .pass_count <<- .pass_count + 1L
    cat(sprintf("  PASS: %s\n", desc))
  }, error = function(e) {
    .fail_count <<- .fail_count + 1L
    msg <- sprintf("  FAIL: %s -- %s", desc, conditionMessage(e))
    .fail_msgs <<- c(.fail_msgs, msg)
    cat(msg, "\n")
  })
}
section <- function(title) cat(sprintf("\n=== %s ===\n", title))
```

### `backend/jobs/utils.R` — `build_donotcalib()` / `prepare_calibration_exclusions()` (service/utility, CRUD+log)

**Analog:** itself, lines 741-801 (both functions already implement the mechanism D-06 keeps).

**Current `build_donotcalib()`** (lines 765-782):
```r
# Build the `donotcalib` argument from the observed death counts. `"other"` is
# explicit and mandatory: vacalibration() applies
# `if (is.null(donotcalib)) donotcalib = "other"`, so supplying ANY value
# suppresses that default -- every entry must include "other" itself or it
# silently starts being calibrated. `intersect()` against `colnames(m)`
# guarantees the package's own name-validation cannot fail, and guarantees no
# raw uploaded cause string can ever reach the argument.
build_donotcalib <- function(va_input) {
  # An empty va_input would produce an UNNAMED empty list, which the package
  # rejects with a bare `stop()` from inside vacalibration(). Say what is wrong
  # here instead.
  if (length(va_input) == 0) {
    stop("No algorithm data to calibrate: va_input is empty.", call. = FALSE)
  }
  zero_sets <- zero_count_causes(va_input)
  setNames(
    lapply(names(va_input), function(k) intersect(colnames(va_input[[k]]), union("other", zero_sets[[k]]))),
    names(va_input)
  )
}
```
D-06 requires adding an explanatory comment here (not a code change) stating that from 2.3.1 on, the package's own `learn` rule (`puncalib < 0.01 | > 0.99`) reaches the same excluded set independently, and the two are unioned inside `vacalibration()` itself (i.e. our explicit `donotcalib` list and the package's internal learn-mask both feed the same final do-not-calibrate set — neither overrides the other). Comment placement: directly above or inside the existing docstring comment block (lines ~765-770), not a separate new function.

**Current `add_log()` call site for D-08** (lines 793-801, `prepare_calibration_exclusions`):
```r
prepare_calibration_exclusions <- function(va_input, job) {
  zero_sets <- zero_count_causes(va_input)
  for (algo in names(zero_sets)) {
    if (length(zero_sets[[algo]]) > 0) {
      add_log(job$id, paste0("Excluding from calibration for ", algo,
                              " (zero observed deaths): ", paste(zero_sets[[algo]], collapse = ", ")))
    }
  }
  list(donotcalib = build_donotcalib(va_input), hidden = unobserved_causes(va_input))
}
```
D-08's version-log line belongs here, one `add_log(job$id, ...)` call added alongside the existing "Excluding from calibration for..." line, e.g.:
```r
add_log(job$id, paste0("vacalibration package version: ", as.character(packageVersion("vacalibration"))))
```
Keep it as a single unconditional line (not inside the `for` loop, since it's not per-algorithm) — matches the file's existing `add_log()` style: plain `paste0()` string, no structured/JSON logging anywhere in this file. This satisfies "keep log simple" from CLAUDE.md.

**Reference for `not_calibrated_causes()` / D-07 (verification only, no edit needed):** lines 1106-1109 combine `.declared_not_calibrated()` and `.passthrough_not_calibrated()` — this is the existing mechanism the phase verifies still discloses sub-1%/above-99% exclusions with no code change; do not touch it.

## Shared Patterns

### Source-only Dockerfile guard tests (no Docker, no R packages)
**Source:** `tests/test_dockerfile_pinning.R` lines 1-19, 39-52
**Apply to:** any new assertion about the Dockerfile's vacalibration install line
```r
lines <- readLines(dockerfile_path)
code <- lines[!grepl("^\\s*#", lines)]  # comment-stripped view; use for all assertions
```
Never grep raw `lines` for pinning assertions — the header prose block deliberately mentions cmake/CRAN URLs/rationale that would make an unfiltered grep self-invalidating (see file's own comment at line ~48).

### Logging convention: plain `add_log(job$id/job_id, string)`, never structured
**Source:** `backend/jobs/utils.R` (10+ call sites, e.g. lines 79, 83, 797, 1357, 1416)
**Apply to:** D-08's version log line
Every log call in this file is `add_log(<id>, <plain string via paste0/paste/sprintf>)`. No JSON, no severity levels beyond ad hoc `[WARN]` prefixing (line 83). Keep the new version line consistent — plain string, no new logging abstraction (CLAUDE.md: "keep log simple").

### R test suite structure: `section()` + `test()` + `quit(status=1)` on failure
**Source:** both test files share this harness (`test_dockerfile_pinning.R` lines 20-38; `test_vacalibration_backend.R` uses the same names throughout)
**Apply to:** both D-03 and D-09 changes
All narrow, single-condition `test()` calls with a human-readable description string as the first argument; failures accumulate but do not halt the script until the final tally triggers `quit(status = 1)`.
