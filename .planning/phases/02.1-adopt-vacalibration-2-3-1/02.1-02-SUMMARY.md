# Phase 02.1 Plan 02: Adapt to vacalibration 2.3.1's widened learn rule Summary

**Documented the redundancy the 2.3.1 learn rule creates, added a one-line-per-job vacalibration version log, and replaced two fixed-cause-set test assertions with derivations from `not_calibrated_causes()` -- including a new deterministic proof that a 0.084 percent cause is disclosed as "not calibrated" rather than mislabelled a zero-count exclusion.**

## Performance

- **Completed:** 2026-09-12
- **Tasks:** 3
- **Files modified:** 2 (+ 1 created: deferred-items.md)

## Accomplishments

- `build_donotcalib()`'s comment block now states plainly that from 2.3.1 on, the package's own `learn` rule (uncalibrated CSMF < 0.01 or > 0.99) independently reaches the same excluded set this function builds, and `vacalibration()` unions the two -- neither overrides the other. The explicit list stays because `zero_count_causes()` still decides what the UI hides, and `prepare_calibration_exclusions()` is the only place the exclusion is logged.
- `prepare_calibration_exclusions()` now logs `vacalibration package version: 2.3.1` as its first statement, before the per-algorithm zero-count loop, so both `run_vacalibration()` and `run_pipeline()` get it with no change to either call site. Section 30's log-count assertions now expect this line (2 lines when a zero-count cause exists, 1 line -- the version line -- when none does), plus a new assertion pinning the version line's exact text.
- Section 12c's flaky "extracted matrix uses the 6 neonate broad causes" assertion is gone. The expected cause set is now `setdiff(neonate_broad_causes, not_calibrated_causes(res90, "interva", neonate_broad_causes))` -- the same function `normalize_mmat()`/`.keep_causes()` use to decide what actually gets dropped -- with a non-vacuity floor requiring at least 2 of the 6 causes to survive. This closes the Phase 1 deferred item "01-03: Pre-existing failure in section 12c" by derivation rather than by re-tuning a number.
- New section 30c proves ROADMAP criterion 4 / D-07 / REQUIREMENTS R1 on `frontend/public/sample_insilicova_neonate.csv`: `congenital_malformation` is exactly 1 of 1190 records (0.084 percent, fixture-sanity asserted); `zero_count_causes()` does not name it; a real `vacalibration()` run (nMCMC=400, nBurn=200, nThin=1) reports it via `not_calibrated_causes(result, "insilicova", causes)`; `Mmat_tomodel` stays a full `1 x 6 x 6`; and the assembled result keeps it in `uncalibrated_csmf` while omitting it from `zero_count_causes` -- disclosed as declined, not hidden as a zero-count exclusion.
- Ran every locally runnable suite: full R suite (656/656, real MCMC), `--input-only` (489/489), the four dependency-free R suites (52+32+23+18 = 125/125), the Dockerfile pinning guard (34/34), the frontend unit suite (34 files, 365/365, 0 skipped), and the production build (succeeds). Frontend lint and the frontend/backend integration check each report one pre-existing, unrelated failure -- proven pre-existing via a throwaway `git worktree` at the pre-phase commit -- and logged to `deferred-items.md` rather than fixed (out of this plan's scope).

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Installed the EAVA R package locally**
- **Found during:** Task 1 (running `Rscript tests/test_vacalibration_backend.R --input-only` to confirm RED)
- **Issue:** The local R library never had EAVA installed. `prepare_eava_input()` calls `EAVA::codEAVA` via `capture.output(print(EAVA::codEAVA))`, which throws an uncaught `loadNamespace` error at section 23 -- not wrapped in `tryCatch`, so it halts the entire script rather than reporting a `FAIL`. This blocked every task's acceptance criterion requiring the suite to reach "All tests passed!".
- **Fix:** `install.packages("EAVA", repos = "https://cloud.r-project.org")`. EAVA is already a declared, legitimate project dependency (in `backend/Dockerfile`'s CRAN install line and `backend/package-manifest.csv`), so this is an environment-setup action, not introducing an unverified package.
- **Files modified:** None (local R library only, not a repo file).
- **Verification:** `Rscript -e 'requireNamespace("EAVA", quietly=TRUE)'` returns `TRUE`; the full suite subsequently runs to completion.
- **Committed in:** N/A (local environment change, no repo diff).
