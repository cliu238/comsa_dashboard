<objective>
Adapt this repository to vacalibration 2.3.1's widened `learn` rule: document the redundancy it
creates, log which package version produced a result, and make the test suite assert the new
behaviour instead of the old fixed cause sets — with a real, deterministic proof that a cause below
1 percent is disclosed as "not calibrated" rather than mislabelled a zero-count exclusion.

Purpose: 2.3.1 now excludes any cause whose uncalibrated CSMF is below 0.01 or above 0.99. That
silently changes results for datasets with a small cause, and it is what made test section 12c flaky
in Phase 1. This plan turns that behaviour change from an undocumented surprise into an asserted,
logged, and explained property.

Output: a commented and version-logging `backend/jobs/utils.R`, a green full R suite including a new
section covering the sub-1 percent rule, and every other local suite run with zero skips.
</objective>

<verified_facts>
Measured on 2026-09-12; use these rather than re-deriving them.

- `frontend/public/sample_insilicova_neonate.csv` maps (via the neonate broad mapping) to column sums
  `congenital_malformation 1, pneumonia 148, sepsis_meningitis_inf 363, ipre 327, other 62,
  prematurity 289` over 1190 records — `congenital_malformation` is 0.084 percent, strictly inside
  the 0-1 percent band and strictly non-zero. It is the only shipped sample with that property, so no
  new fixture file is needed.
- Because that cause is non-zero, `zero_count_causes()` will not name it: it can only be disclosed
  through `not_calibrated_causes()`, which is exactly the path ROADMAP criterion 4 requires.
- The learn rule keys off the uncalibrated CSMF (the observed share), not an MCMC draw, so the
  exclusion of a 0.084 percent cause is deterministic, unlike the section 12c flakiness it explains.
- `not_calibrated_causes(result, algo_name, causes)` works on a single-algorithm result even when
  `donotcalib_tomodel` carries no algorithm rowname (`.declared_not_calibrated()` falls back to row 1).
- Section 12c lives inside the `if (!input_only)` block (lines 810-1561); section 30 lives after it
  and therefore also runs under `--input-only`.
- `vacalibration 2.3.1` ships `data/comsamoz_CCVAoutput.rda`, which the locally installed 2.0 lacked —
  section 2b, which used to halt the suite on this machine, now has its fixture.
- Stan models are compiled once per R session (memoised closures in `R/model_utils.R`) and
  `.onLoad()` sets `rstan_options(auto_write = TRUE)`, so the full suite pays the ~20-40 s compile at
  most once.
