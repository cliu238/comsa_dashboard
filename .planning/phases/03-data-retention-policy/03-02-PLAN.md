reads provably the number the backend enforces.

(CONTEXT D-01); this plan is the documented half — plus the guard that stops the documented number and
the enforced number drifting apart, which is the failure mode D-09 singles out.

Output: one sentence in the job list, a Data retention section in both READMEs, a corrected comment in
the migration that used to state no expiry existed, and a dependency-free test tying the three
statements of the window together.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend constant -> user-facing copy | A user decides whether to download results based on this sentence; if it understates the window, data they expected to keep is already gone |
| repository documentation -> future maintainer | A comment stating that no expiry exists would lead a maintainer to build a second, conflicting policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Repudiation | the user-facing window diverging from the enforced window | high | mitigate | Section 4 of `tests/test_retention.R` compares the integer in `JobList.jsx`'s `RETENTION_NOTICE` and in README.md's Data retention section against `RETENTION_DAYS`, numerically; CI runs the suite on every push, so divergence fails the build rather than reaching a user. |
| T-03-08 | Tampering | a schema edit disguised as a documentation change | medium | mitigate | The migration diff is asserted to contain only `--` comment lines, and no migration other than `003_input_file_storage.sql` may be touched. |
| T-03-09 | Information Disclosure | the notice text | low | accept | The sentence is static copy; it contains no job data, no identifiers and no user information, and is rendered to an already authenticated user. |
| T-03-10 | Spoofing | injecting markup through the notice | low | accept | The copy is a module constant rendered as a JSX text child, so React escapes it; there is no `dangerouslySetInnerHTML` and no user input path into the string. |
